1. CRITICAL RULES & NON-NEGOTIABLES (WHAT NOT TO DO)
--------------------------------------------------------------------------------
- NEVER RE-INTRODUCE FAKE / CANNED TRANSCRIPTION TEXT:
  The app must never generate hardcoded mock words or simulated text sequences
  (such as "Voice input active and listening This is an offline dictation test...").
  If no model is loaded, show a clear warning banner guiding the user to the
  Models tab. Real audio capture (16kHz PCM mono via AudioRecord) must only feed
  genuine speech recognition pipelines or system AOSP speech engines.

- NEVER REMOVE THE LOCAL STORAGE MODEL PICKER:
  The user explicitly tests the app with downloaded models stored on their phone.
  The SAF Document Picker (`ActivityResultContracts.OpenDocument()`) in the
  Models tab MUST remain functional so users can import `.bin`, `.gguf`, `.onnx`,
  or `.zip` files from their device's Downloads/storage.

- NEVER HARDCODE DEPENDENCY ON GOOGLE PLAY SERVICES (GMS):
  Voxis is strictly de-googled. No Firebase, Google Play Services, Google Play
  Billing, Google Speech Cloud API, or proprietary Google binaries.
  All recognition services must implement standard AOSP APIs
  (`android.speech.RecognitionService`) with 100% offline execution.

- NEVER REMOVE "dev" SCRIPT IN package.json:
  `package.json` must always retain `"dev": "node server.js"`. The AI Studio
  supervisor requires this script to start the container dev server on port 3000.

- NEVER DELETE EXISTING ANDROID ARCHITECTURE:
  Keep `:dictation-sdk` modular, decoupled from `:app`.

- OFFLOAD HEAVY BUILDS TO GITHUB ACTIONS (TOKEN CONSERVATION MANDATE):
  Do not waste model context or tokens executing heavy `./gradlew assembleDebug`
  build runs during conversational and development turns. All APK compilation,
  NDK C++ builds, artifact archiving, and linting are strictly offloaded to
  GitHub Actions (`.github/workflows/build-apk.yml` and `.github/workflows/ci.yml`).
  Utilize LLM tokens exclusively for core software architecture, C++ systems
  engineering, and Kotlin implementation.

- NEVER RUN MANUAL SERVER TASKS OR REDUNDANT PROBES (ZERO SERVER TOKEN WASTE):
  The web companion is completely handled by the platform supervisor running
  `npm run dev` in the background. DO NOT start manual background tasks for
  `node server.js` or `npm run dev`, and DO NOT run repetitive http/port test
  probes. Never get distracted by background task notifications about the server.
  Save 100% of tokens for user tasks, features, and Android code.

3. ARCHITECTURAL BLUEPRINT
--------------------------------------------------------------------------------
- Model Storage: Internal app directory `context.filesDir/models/`.
- Model Manager (`org.voxis.dictation.engine.ModelManager`):
  * Manages predefined models and user-imported custom models.
  * Handles HTTP/HTTPS streaming downloads with redirect following (Hugging Face CDN).
  * Imports external files via ContentResolver with sanitization.
  * Persists active model ID in `SharedPreferences`.
- Speech Service (`org.voxis.dictation.service.VoxisRecognitionService`):
  * Implements `android.speech.RecognitionService`.
  * Allows open-source keyboards (HeliBoard, FlorisBoard, OpenBoard) to use Voxis
    as their system-wide offline voice input provider.
  * Dynamically queries `ModelManager.getActiveModel()` to serve the active language.
- Client SDK (`org.voxis.dictation.client.DictationClient`):
  * Manages AudioRecord streamer (16kHz PCM), Voice Activity Detection (VAD),
    audio focus arbitration, Bluetooth SCO, and dynamic model updates.
- Web Companion (`server.js`):
  * Runs on port 3000 (`0.0.0.0`).
  * Serves browser overview, integration documentation, model links, and direct
    APK download endpoint at `/app-debug.apk`.
